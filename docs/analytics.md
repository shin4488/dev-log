# サイトの計測

目的は、訪問者が記事・自己紹介を見て、制作物や外部プロフィールに興味を持ったかを知ること。
イベント総数の増加そのものを成果にしない。

## 何を知るために計測するか

| 見る指標                     | 記録方法                                                                        | 分かること・改善への使い方                                 |
| ---------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 訪問者数、流入元、端末       | GA標準のユーザー・セッション・集客・デバイス情報を継続                          | 紹介元の効果、PCとスマホの違いを比較する                   |
| ページ別の閲覧数             | `page_view`。初回と画面遷移完了時に1回                                          | 読まれている記事、入口になっているページを知る             |
| 各欄に到達した人数           | `section_view`。見出しの半分以上を1秒連続で表示したら、1ページ表示につき各欄1回 | 個人開発や開発経験まで見られているか。見出し・配置を見直す |
| 制作物を開いた人数           | `project_click`。画像・タイトルのクリック。中クリックも対象                     | 興味を持たれた制作物を知り、紹介文や順番を見直す           |
| 外部プロフィールを開いた人数 | `profile_click`。自己紹介ページのSNS等のリンクのクリック                        | GitHubや技術記事など、詳しい情報へ進んだかを知る           |
| 記事が読まれた目安           | `article_read`。本文末尾に到達し、タブ表示中の累計時間が30秒以上になったら1回   | 閲覧数だけでなく、本文まで届いた記事を比較する             |
| その他の外部リンクのクリック | GA拡張計測の `click` を継続                                                     | 記事中の参考リンクなどへの移動を確認する                   |

「人数」はイベント数ではなく、該当イベントを起こした**総ユーザー数（期間内のユニークユーザー数）**で集計する。同じユーザーとして識別されれば繰り返し閲覧しても1人だが、端末・ブラウザの違いやCookieの削除で別ユーザーになる場合がある。ページ別の人数は重複するため足し合わせない。自身のアクセスを除外する設定は未追加。

クリック率は同じ期間・ページ・端末条件で「クリックしたユーザー数 ÷ 対象ページを見たユーザー数」。記事の閲覧割合も「article_read のユーザー数 ÷ 同じ記事の page_view のユーザー数」とする。section_view は見出し表示の目安であり、欄全体の読了や制作物ごとの表示回数ではない。

制作物のクリックは移動先の利用開始・登録・購入の証明ではない。article_read も読了や理解の証明ではない。訪問数が少ないため、基本は過去12か月で全体の傾向を見る。最近の変化は過去3か月を補助的に確認し、比較するときは同じ長さの期間・条件をそろえる。母数が少ない場合は件数を併記して割合だけで結論を出さない。新しく追加した計測項目は公開後のデータだけが対象となり、期間を広げても過去のデータは増えない。

## GA側の設定

対象は dev-log。公開ビルドでは、既存の環境変数 `GOOGLE_ANALYTICS_MEASUREMENT_ID` を使用する。

2026-09-12に管理画面で次の拡張計測を停止した。過去データの削除は行わない。

| 停止する計測                         | 理由                                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| スクロール `scroll`                  | ページ全体の90%到達だけでは、どの欄が見られたか分からない。新実装の section_view・article_read で目的別に把握する |
| 履歴変更による自動ページビュー       | Astroの画面遷移完了時にサイト側から送る page_view と重複し得る                                                    |
| サイト内検索 `view_search_results`   | 現在サイト内検索がない                                                                                            |
| 動画の再生・進捗・完了               | 現在対象の埋め込み動画がない                                                                                      |
| ファイルダウンロード `file_download` | 現在公開記事に対象リンクがない。配信機能自体は残し、対象コンテンツを追加した際に再検討する                        |

フォーム操作は元から無効。ページ閲覧・離脱クリックと、first_visit / session_start / user_engagement など基本集計に必要な自動イベントは残す。`click` と project_click / profile_click は対象が重なるため、件数を足し合わせない。目的別分析には新イベントを使う。

コード側では、ページ内の位置やURLパラメータで閲覧先を分けていた旧 page_path を、パスのみの記録へ変更した。page_location は流入判定のためクエリを保持し、ハッシュは除く。ページタイトル・種類・直前のページも画面遷移後の値を明示する。外部リンクの独自イベントではリンク先のクエリ・ハッシュを送らない（GA標準の click とは別）。

イベント単位のカスタムディメンション：

| GA上の名前             | イベントパラメータ | 値                                                          |
| ---------------------- | ------------------ | ----------------------------------------------------------- |
| ページの種類           | `page_type`        | about / blog / tags / post / not_found                      |
| 表示された欄           | `section_name`     | sns（リンク）/ projects（個人開発）/ experience（開発経験） |
| クリックされたリンク名 | `link_name`        | 制作物名または外部プロフィール名                            |

page_path / page_location / page_title / page_referrer / link_url は標準項目を使い、重複するカスタム定義は作らない。探索ではイベント名を絞り込み、各分類と総ユーザー数・イベント数を組み合わせる。主要な成果は project_click、補助的な成果は profile_click とする。

## 公開と確認

レポートは「レポート → カスタム ダッシュボード → dev-log｜サイト改善レポート（総ユーザー数＝ユニークユーザー数）」から開く。ユーザー設定のデフォルト期間は30日間に設定済み。この設定は本人が見るレポート全体に適用される。長期の傾向を見る際は、右上の期間を過去12か月に変更する。レポート自体に1年間のデフォルト期間は保存できない。

- 新イベントはコードの公開後に収集が始まる。GA設定だけでは発生しない。過去に遡って追加できない。
- 新イベントが届いたらリアルタイムで確認し、通常レポートへの反映後に比較する。公開日の前後では計測条件が違うことに注意する。
- 開発サーバや測定ID未設定時は収集しない。ローカルの本番プレビューは必ず `G-TEST` でビルドし、本物の測定IDを使わない。
- `GOOGLE_ANALYTICS_MEASUREMENT_ID=G-TEST yarn build` 後に `yarn test:e2e`。テストはGAへの外部送信を遮断し、送信キューに積まれるイベント・画面遷移・リンク操作を確認する。
- 単体テストは背景タブの時間除外、表示時間の条件、ページ離脱時の処理停止も検証する。
